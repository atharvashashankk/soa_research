# GitHub project selection and evidence

The project library is a separate implementation catalog, checked on 2026-10-13. It does not change the paper count, screening denominator, publication status, or semantic paper clusters.

Include a GitHub repository when its own documentation shows either (1) a coding-agent harness usable for software development, or (2) a memory method or service that could be connected to such a harness. Prefer repositories with inspectable code and documentation over product landing pages. Record the repository URL, a specific source for the described behavior, a concise research fit, and a boundary on what has actually been verified. Do not infer compatibility, performance, maturity, or a memory benefit from repository popularity.

Project tags reuse the paper taxonomy only as topical labels. `paperIds` are conceptual reading links, not claims that a paper evaluated the project. The project catalog currently has 11 repositories: six harnesses or combined harness-memory systems and five memory layers. The primary evidence is each project's GitHub repository or documentation within it. No project was installed or benchmarked for this snapshot. Recheck repository behavior, licensing, and integration requirements before using any project in an experiment; GitHub branches can change after the recorded check date.
